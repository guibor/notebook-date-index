#+title: Notebook Dates

* Objective
Find newly created notebook pages by their original date without cluttering or
changing the user's existing table of contents.

* Requirements
- Own a standalone private GitHub repository, =guibor/notebook-date-index=.
- Keep the Dates feature set aligned across Pro and Move using separately
  qualified exact-firmware branches, release evidence and a compatibility matrix.
- Synchronize date-history metadata for the same notebook between Pro and Move.
  Pages created on either device retain their original recorded date on both.
- Support offline creation followed by idempotent merging, without duplicate
  date/page entries or replacing one device's whole index with the other's.
- Verify stable notebook/page identity across native sync before implementation;
  never match by notebook title or page number. Copies remain separate notebooks.
- Sync arrival is not page creation. Preserve each entry's original timestamp,
  date, timezone and offset, regardless of the receiving device's settings.
- Preserve unrelated device settings, especially Gestik. Dates metadata sync
  is not permission to copy all device settings or automatically install builds.
- Per-notebook opt-in, default off. A copied notebook has a new ID and stays off.
- Separate Dates panel under the notebook's three-dot settings menu, with an
  additional entry under More tools when available. One group per local date; tap first
  created surviving page; expand individual page links.
- Record stable page IDs after explicit successful creation. Cover ordinary
  toolbar/swipe add, Page Overview add/duplicate, conversion and Quick Sheets.
- Enable/re-enable baselines all current pages without invented old dates.
- Pause preserves history. Reorder resolves IDs to current page positions.
  Delete hides missing pages; undo reuses their original dates.
- Do not infer creation from file mtime or a generic page-count change.
- Imported/moved-in pages remain undated. Ambiguous events fail closed.
- Serialize durable writes to an independent private folder, with atomic
  replacement and recoverable prior version. Never write native notebook/TOC.
- Preserve Pro/Move independence, exact firmware/runtime gates, all existing
  QMD/Gestik bytes, and read-only root. No boot/firmware/kernel changes.
- First install is a non-recording preview. Functional promotion follows
  physical UI acceptance, then a disposable-notebook acceptance exercise.
- The deployed v1 index is currently local-only; shared date history is required
  next, not yet implemented. Sync errors/offline use must not block stock page
  creation or existing local date navigation.
- Test the real Qt XMLHttpRequest queue against the actual HTTP service,
  including Qt's JSON Content-Type charset parameter. A mocked popup and a
  curl-only health check do not prove this interface works.
- Default date timezone is =Asia/Jerusalem=, with automatic daylight saving.
  Make it configurable in the Dates panel and a device-local settings file.
  A timezone change affects future records only, never existing dates or the
  tablet's system timezone. Each device maintains its own choice.

* Changed requirements
- User clarified that "in sync" includes actual Dates history for the same
  notebook, not only app feature/version parity. The prior no-cross-device-index
  requirement is superseded. Notebook content/normal ToC remain unmodified;
  unrelated device settings still remain independent.
- Maintenance scope expands from the initial Pro-only implementation to
  shared Pro/Move features. Move remains unqualified until independently ported.
- A local-only repository is insufficient; publish and maintain this app's
  own GitHub repository, distinct from firmware markers and other apps.
- The visible preview failed to load because the backend rejected Qt's valid
  =application/json;charset=UTF-8= header. Accept parsed JSON with UTF-8 while
  retaining token, Origin, HTTP-method and body validation. Prefer a backend-only
  repair, preserving the live tablet UI and every QMD byte.
- More tools is hidden by firmware when the toolbar container is tall; the
  user could not reach the first preview there. The three-dot Notebook
  settings menu is now the primary entry point without forcing overflow on.
- User selected Israel time, configurable. Tablet UTC offset is no longer the
  source of the date boundary; the saved IANA timezone computes it instead.
- Originally considered automatic daily headings in the normal ToC or native
  date tags. User accepted the recommended separate index instead.
- No requirement to backfill dates for pages created before opt-in; their true
  dates are unknown. No firmware-survival service is required. The former
  exclusion of cross-device index sync is superseded by the clarification above.
