#+title: Notebook Dates

* Branch target
This checkout is =beta/move/3.28.0.169=. It keeps the notebook-menu entry and
uses the exact Chiappa resource/runtime profile; never use the Pro installer.

* Objective
Find notebook pages by creation day or their saved last-edit day, without
cluttering or changing the user's existing table of contents.

* Date-focused revision (2026-09-19)
** Calendar polish (revision 6)
- Show one focused month, with previous/next arrow controls, rather than a
  scrollable month stack. Start at the latest dated month; traverse empty months
  between the earliest and latest dates. Back from a day retains the focused month.
- Every visible civil date is real, including previous/next-month spillovers.
  Adjacent dates are subdued but retain dots and page navigation when relevant.
- Use a compact two-icon List/Calendar picker in the header. The highlighted
  icon means the current view; it does not name the next action. Created/Modified
  remains the only full-width segmented control. No text-only layout button.
- Remove avoidable opening flashes: prepare before showing, retain only matching
  notebook/date-basis cache, refresh without clearing it, avoid identical model
  replacement, and disable popup dimming/transitions locally. Never show another
  notebook's cached dates. Failed refresh visibly identifies retained cached data.
- Signal: no intermediate empty/list frame on a warm Calendar reopen; arrow,
  spillover and page selection work at both screen sizes. Automated delayed-response
  checks are a release gate, not proof of physical e-ink refresh behavior.
- Preserve all recording, sync, native notebook, QMD, writer and device-setting
  behavior. Only the external presentation panel/helper need replacement.
** Navigation refinement and physical Move rollout
- Keep Created / Modified as the only full-width segmented control. The compact
  header picker switches List / Calendar without changing the date basis.
- Modified-calendar day selection orders pages by current numeric page number,
  not last-edit timestamp. Do not mutate the list view's existing order.
- Pro: calendar-icon sidebar entry immediately above BetterTOC. Retain the
  notebook menu fallback only when the toolbar is too short for direct tools.
  Move: keep Dates in the three-dot notebook menu, with no extra sidebar tool.
- Install on independently qualified Move .169 and verify real shared-notebook
  history using its own sync credential. Keep gesture/tracking/timezone settings
  device-local; do not equate machine checks with physical pen acceptance.
** Calendar and sync follow-through
- Created / Modified and List / Calendar are independent choices. Switching
  presentation never changes tracking, stored dates, or the selected date basis.
- Calendar arrows navigate consecutive months, including empty intervening
  months. Sunday-first weeks fit the Israel default. Mark only days
  with locally available pages in the selected date view, using a high-contrast dot.
- Tapping a marked day opens its page choices inside Dates; Back returns to
  the same calendar position. Undated pages and estimated dates remain explicit.
- Calendar is a read-only projection of the same groups as List. Test leap years,
  year boundaries, empty months, mode switches, stable IDs and compact layouts.
- Then finish the authorized md-server sync rollout, preserving both devices'
  local tracking/settings and recording machine versus physical acceptance separately.
** Worldview and hypothesis
- Fact: on qualified Pro .169, native =cPages.pages[].modifed= contains saved
  page last-modification epoch milliseconds. There is no verified page creation
  timestamp; CRDT =timestamp= and =scrollTime= are not substitutes.
- Fact: the user reports single-device functionality works; two-device physical
  acceptance remains unperformed. The visible settings-heavy UI is unsatisfactory.
- Hypothesis: a browsable date hierarchy and a Created/Modified switch make
  finding pages easier, while separating settings keeps attention on history.
- Objective: navigate by either date meaning without confusing estimated older
  dates with observed creation or interrupting normal page creation.
- Signal: correct date/page navigation and preserved writing flow. There is no
  measured usability baseline; physical aesthetic/usability acceptance is pending.
- Engineering release gates: all metadata/backfill/provenance tests pass; real
  Qt transport and page-creation regression pass; stock/runtime/settings hashes
  stay unchanged; guarded Pro runtime has no new Dates errors/restarts.
- Pass: gates pass and user accepts navigation/readability. Fail: stock page
  creation blocks, native files change, or estimated dates masquerade as creation.
  Inconclusive: offline tests pass but physical navigation has not been checked.
** New behavior
- Main panel shows Created / Modified, a compact settings gear, and date rows.
  Group days into collapsible months, and years above months for multi-year data.
  Day taps jump to the first surviving page; expand shows individual pages.
- Modified reads only built-in page modification metadata and works with
  tracking off. Missing/invalid dates remain undated. No file-mtime inference.
- When enabling tracking, offer an unchecked option to initialize undated
  pages from their saved modification dates. Store this one-time estimate with
  provenance; never overwrite recorded dates or continuously move estimates.
- Real creation observations win over estimated baselines during sync. Preserve
  both in the event journal. Upgrade the hub before syncing new estimate fields.
- Move tracking, timezone, backfill and sync status behind in-panel settings.
  Israel time remains the default. Changed timezone re-groups Modified now but
  affects Created only for future observations/estimates.
- Make the hub endpoint/device names explicit deployment configuration. No
  personal server default in distributed code. Preserve existing private config.
- Stay on the current Pro branch and implement directly, with internal automated
  and visual QA but no user preview gate for this accepted app's revision.

* Requirements
- Prepare a shareable, user-oriented repository with a feature tour, screenshots,
  exact compatibility, installation/recovery instructions, optional self-hosting,
  developer tests, privacy guidance and dependency/license provenance.
- Distinguish source availability from general tablet installability. Preserve
  exact-device guards; do not describe owner-pinned scripts as a public installer.
- Prepare an unpublished r/Remarkable post with honest firmware/install limits;
  request moderator permission because the current rules prohibit self-promotion.
- Keep repository visibility and license selection explicit owner decisions;
  historical personal operational metadata must be reviewed before publication.
- Stock page creation must succeed even if Dates observation, storage or sync
  fails. Pass the caller's native controller explicitly; do not assume native
  singleton imports are visible inside the shared Values module.
- Use flat high-contrast e-ink controls, readable labels and 64-pixel touch
  targets in Dates, including the timezone selector and date/page rows.
- Own a standalone private GitHub repository, =guibor/notebook-date-index=.
- Keep the Dates feature set aligned across Pro and Move using separately
  qualified exact-firmware branches, release evidence and a compatibility matrix.
- Synchronize date-history metadata for the same notebook between Pro and Move.
  Pages created on either device retain their original recorded date on both.
- Support offline creation followed by idempotent merging, without duplicate
  date/page entries or replacing one device's whole index with the other's.
- Verify stable notebook/page identity across native sync before implementation;
  never match by notebook title or page number. Copies remain separate notebooks.
- Sync arrival is not page creation. Preserve each entry's original timestamp,
  date, timezone and offset, regardless of the receiving device's settings.
- Preserve unrelated device settings, especially Gestik. Dates metadata sync
  is not permission to copy all device settings or automatically install builds.
- Per-notebook opt-in, default off. A copied notebook has a new ID and stays off.
- Separate Dates panel under the notebook's three-dot settings menu, with an
  additional entry under More tools when available. One group per local date; tap first
  created surviving page; expand individual page links.
- Record stable page IDs after explicit successful creation. Cover ordinary
  toolbar/swipe add, Page Overview add/duplicate, conversion and Quick Sheets.
- Enable/re-enable baselines current pages; explicit optional last-modified
  initialization is the only permitted estimated backfill.
- Pause preserves history. Reorder resolves IDs to current page positions.
  Delete hides missing pages; undo reuses their original dates.
- Do not infer creation from file mtime or a generic page-count change.
- Imported/moved-in pages remain undated unless explicitly included in the
  optional baseline. Ambiguous creation events fail closed.
- Serialize durable writes to an independent private folder, with atomic
  replacement and recoverable prior version. Never write native notebook/TOC.
- Preserve Pro/Move independence, exact firmware/runtime gates, all existing
  QMD/Gestik bytes, and read-only root. No boot/firmware/kernel changes.
- Initial Pro installation used a non-recording preview. The user subsequently
  requested direct guarded upgrades and Move installation; recording still
  defaults off per notebook/device, with physical acceptance recorded separately.
- Both tablets now sync creation history to the private hub; actual Pro-to-Move
  delivery is verified. Sync errors/offline use must not block stock page
  creation or existing local date navigation.
- Test the real Qt XMLHttpRequest queue against the actual HTTP service,
  including Qt's JSON Content-Type charset parameter. A mocked popup and a
  curl-only health check do not prove this interface works.
- Default date timezone is =Asia/Jerusalem=, with automatic daylight saving.
  Make it configurable in the Dates panel and a device-local settings file.
  A timezone change affects future records only, never existing dates or the
  tablet's system timezone. Each device maintains its own choice.

  requirement is superseded. Notebook content/normal ToC remain unmodified;
  unrelated device settings still remain independent.
- Maintenance scope expands from the initial Pro-only implementation to
  shared Pro/Move features. Move remains unqualified until independently ported.
- A local-only repository is insufficient; publish and maintain this app's
  own GitHub repository, distinct from firmware markers and other apps.
- The visible preview failed to load because the backend rejected Qt's valid
  =application/json;charset=UTF-8= header. Accept parsed JSON with UTF-8 while
  retaining token, Origin, HTTP-method and body validation. Prefer a backend-only
  repair, preserving the live tablet UI and every QMD byte.
- More tools is hidden by firmware when the toolbar container is tall; the
  user could not reach the first preview there. The three-dot Notebook
  settings menu is now the primary entry point without forcing overflow on.
- User selected Israel time, configurable. Tablet UTC offset is no longer the
  source of the date boundary; the saved IANA timezone computes it instead.
- Originally considered automatic daily headings in the normal ToC or native
  date tags. User accepted the recommended separate index instead.
- Originally no backfill was requested; true old creation dates remain unknown.
  Optional estimated initialization now supersedes that exclusion. No
  firmware-survival service is required. The former
  exclusion of cross-device index sync is superseded by the clarification above.
